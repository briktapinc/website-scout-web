Design agent trigger

When a design job becomes waiting_on_agent (new assign, redesign, improvements, or questions answered), the app always writes a JSON trigger file and can ping you or run a shell command. Filter on reason: assigned, redesign, improvements, questions_answered. The webhook below fires only when a redesign or improvements request is submitted. Failures are logged and never block the queue.
Placeholders: {{job_id}}, {{reason}}, {{status}}, {{message}}. Also sets env WS_DESIGN_JOB_ID, WS_DESIGN_REASON. Use a watcher script or anything that wakes your MCP agent. Leave blank to skip.
POSTed as JSON only when redesign or improvements is queued (reason: redesign | improvements). Body includes job_id, request_kind, reason, status, title, timestamp. Leave blank to skip. Failures go to the activity log and never block the queue.
When set, sent as Authorization: Bearer … and X-Webhook-Secret. Leave blank for no auth header.
Default is design-agent-trigger.json beside the SQLite DB. Watch this file or read it after a redesign / improvements send.

Lead discovery (Tavily)

Required for Leads → Discover with the tavily provider. Get a key at tavily.com. Stored locally and never shown again. Without a key, discovery returns PROVIDER_NOT_CONFIGURED. Discovery runs a few local-business query variants and prefers advanced depth for richer snippets.
Advanced is recommended for local lead discovery. Change applies on the next Discover run.
